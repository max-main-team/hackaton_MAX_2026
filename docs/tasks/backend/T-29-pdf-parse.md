# T-29 — Парсинг резюме из PDF (бек)

- **Статус:** ✅
- **Спека:** `docs/backend/spec-pdf-parse.md`
- **Зависимости:** T-06 (резюме), T-27 (AI-клиент z.ai)
- **Разблокирует:** T-30 (фронт: загрузка PDF)

## Что сделать

- `POST /api/v1/my/resume/parse` — тело `{"text": "...", "source_name": "resume.pdf"}`:
  - текст резюме (извлекается на фронте через pdfjs, не файл);
  - AI (GLM через z.ai) структурирует текст в поля резюме по нашей схеме;
  - валидация/кламп: enum'ы work_format/employment_type через словарь синонимов
    («удалённо»→remote, «полный день»→full_time и т.п.), опыт 0..600,
    min/max зарплаты свап при min>max, отрицательные → null;
  - upsert черновика: `source='file_parse'`, `source_text=<весь текст>`,
    `is_active=false` (новый черновик) / сохранение прежнего `is_active`
    (если у юзера уже было резюме);
  - если AI недоступен/ошибка → черновик только с `source_text`, остальные
    поля пустые, юзер заполнит вручную; ответ всё равно 200 с notes.
- Лимиты: text непустой, ≤30 000 символов (иначе 400).
- Ответ: `{"resume": {...}, "ai_comment": "что извлекли / что не нашли"}`.

## Критерии приёмки

- [ ] Реальный текст резюме (СПб, Go-разработчик) → черновик с заполненными полями в БД.
- [ ] `is_active=false` у черновика; после PUT юзера — активно.
- [ ] `source_text` сохранён полностью; PUT юзера его не затирает.
- [ ] AI недоступен → 200 + пустые поля + source_text + notes.
- [ ] `go build/vet/test/gofmt` — чисто; юнит-тесты на normalize + промпт.
