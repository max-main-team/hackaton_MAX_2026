# T-36 — Все кандидаты для компаний (вне метчинга)

- **Статус:** ✅
- **Спека:** docs/backend/spec-matching.md (расширение, контракт существующих ручек не меняется)
- **Зависимости:** T-04 ✅, T-09 ✅

## Что сделано

- Бек: `GET /api/v1/candidates?q&limit&offset` — все активные резюме
  кандидатов независимо от вакансий и скоринга; роль recruiter обязательна
  (иначе 403); поиск по title/skills/city (ILIKE, ≤100 символов);
  пагинация limit 1..100 (20 по умолчанию), total через count(*) OVER().
  Ответ `{total, items: [{user, resume}]}` — без score/breakdown.
- Репозиторий: `ResumeRepo.ListCandidateCards` (JOIN users, только
  role=candidate, сортировка по updated_at DESC).
- Фронт: экран `/company/candidates` — поиск с дебаунсом 300 мс,
  список карточек, разворот с полным резюме (форматы, навыки, about,
  образование, зарплата), «Показать ещё»; вкладка «Кандидаты» в таббаре
  рекрутера. Приглашение — из подбора по вакансии (там контекст vacancy).

## Тесты

- Интеграционные с реальной БД: рекрутер видит всех, поиск фильтрует,
  неактивные скрыты, кандидат получает 403, пагинация limit/offset/total.
  Данные изолированы маркерами (общая dev-БД).
