# Docs — ИИ-артефакты проекта

Документы-контекст для ИИ-агентов и новых участников. Описывают фактическое
состояние кода в репозитории. При изменении кода — обновляйте соответствующий
файл в этом же коммите.

## Структура

```
docs/
├── common/               — общее для всей команды
│   ├── idea.md           — общая идея продукта
│   ├── features.md       — список фич: основные и второстепенные
│   ├── plan.md           — план: скоуп хакатона, этапы, задачи бек/фронт
│   ├── stage-1.md        — этап 1 пошагово: шаги, границы, DoD
│   └── status.md         — трекер прогресса: что сделано / не сделано
├── tasks/                — РАБОЧИЕ ЗАДАЧИ (вести здесь, бек и фронт параллельно)
│   ├── README.md         — правила ведения, легенда статусов, шаблон задачи
│   ├── backend/          — T-01…T-12, T-19 + README-индекс
│   └── frontend/         — T-13…T-18 + README-индекс
├── bugs/                 — БАГ-РЕПОРТЫ (один баг — один файл + README-индекс)
├── backend/
│   ├── architecture.md   — слои, поток запроса, конфиг, запуск
│   ├── api.md            — спецификация HTTP-эндпоинтов (текущее состояние)
│   ├── database.md       — схема БД, конвенции миграций
│   ├── spec-auth.md      — SPECS: initData-подпись, JWT, RequireAuth
│   ├── spec-domain.md    — SPECS: миграции 000002/000003, репозитории
│   ├── spec-api.md       — SPECS: полный контракт API v1 (целевое состояние)
│   └── spec-matching.md  — SPECS: скоринг, TTL, еженедельный опрос
├── max/                  — выжимка документации MAX (dev.max.ru)
│   ├── README.md         — индекс + ключевые факты
│   ├── mini-app-setup.md — бот, привязка мини-аппа, диплинки
│   ├── bridge.md         — справочник window.WebApp
│   ├── init-data.md      — структура initData + алгоритм валидации + Go
│   └── bot-api.md        — Bot API: сообщения, кнопки, лимиты
└── frontend/
    ├── architecture.md   — структура, прокси, команды
    ├── max-bridge.md     — интеграция с MAX (window.WebApp, initData)
    └── spec-ui.md        — SPECS: роуты, экраны, компоненты, API-биндинги
```

Файлы `architecture.md`/`api.md`/`database.md` описывают код **как есть**;
файлы `spec-*.md` — **целевое** состояние MVP, по ним имплементятся тикеты
из `tasks/`. Статус всех работ — `common/status.md`; правила ведения
задач — `tasks/README.md`. Архитектура каталогов всего репозитория —
[`ARCHITECTURE.md`](../ARCHITECTURE.md) в корне.

## Кратко о проекте

Мини-приложение для мессенджера MAX. Монорепозиторий:

| Папка      | Стек                                        |
|------------|---------------------------------------------|
| `backend/` | Go 1.27, Echo v4, pgx v5 (pgxpool), Postgres |
| `frontend/`| React 19, TypeScript, Vite 8, oxlint         |

Локально: Postgres в Docker торчит на **5433** (5432 занят локальным Postgres
разработчика), бекенд на `:8080`, фронт на `:5173` с прокси `/api`.

## Важные ограничения и долги

- Проверка подписи `initData` на бекенде **не реализована** (см.
  `docs/backend/api.md`) — перед продом обязательно сделать.
- Авторизация stateless: JWT/сессии не введены, `POST /auth` просто upsert'ит
  пользователя и возвращает его.
