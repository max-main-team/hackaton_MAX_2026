# BUG-01 — Ведущий ноль в поле «Опыт работы» не стирается

- **Приоритет:** 🟠 заметная поломка ввода
- **Экран:** рекрутер → «Новая вакансия» → секция «Условия» → «Опыт работы»
- **Также затронуто:** экран кандидата «Моё резюме» → «Опыт, мес» (тот же паттерн)

## Шаги воспроизведения

1. Открыть `/company/vacancies/new`.
2. В поле «Опыт работы» стереть значение `0` клавишей Backspace.
3. Нажимать Backspace дальше / попробовать впечатлить своё значение.

## Фактический результат

- Backspace: `3` → `0` → `0` → … Поле никогда не становится пустым,
  ведущий ноль не стирается.
- Проверено вживую на проде (Playwright, `/company/vacancies/new`):
  после ввода `3` и одного Backspace значение возвращается в `0`.

## Ожидаемый результат

- Поле можно полностью очистить; пустое значение трактуется как `0`
  (или `null`) при отправке формы, а не возвращается в инпут.

## Причина

Контролируемый инпут с мгновенным `Number()`:

```tsx
<input type="number" value={form.min_experience_months}
  onChange={(e) => set('min_experience_months', Number(e.target.value))} />
```

`Number('') === 0` → стейт снова `0` → React рендерит `0` вместо пустой
строки. Места: `frontend/src/routes/recruiter/vacancy-new.tsx`,
`frontend/src/routes/candidate/resume.tsx`.

## Как чинить (предложение)

Хранить в стейте строку (или `number | null` c `''` при пустом вводе),
`Number()` применять только при отправке/блюре. Аналогично для окладов
(там уже `null`, но тот же риск при `Number('')`-паттерне).

## Фикс

- Draft-стейт для числовых инпутов: пустая строка отображается как есть,
  `Number()` применяется только для стейта формы (пусто = 0).
- Файлы: `recruiter/vacancy-new.tsx`, `candidate/resume.tsx`.
- Проверено вживую: `3` → Backspace → пустое поле.
- Коммит: см. `git log` (BUG-01…05).
