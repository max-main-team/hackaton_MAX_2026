# BUG-03 — Не работают свайпы влево/вправо в подборе кандидатов

- **Приоритет:** 🟠 заметная поломка флоу (фича 1.5 из idea/features)
- **Экран:** рекрутер → «Подбор» (`/vacancy/:id/feed`)

## Шаги воспроизведения

1. Открыть `/vacancy/:id/feed` (таб «Подбор»).
2. Свайпнуть карточку кандидата влево или вправо (тач/мышь).

## Фактический результат

Карточка не реагирует на свайп. Отбор работает только кнопками
«Пропустить» / «Пригласить». В коде нет ни одного обработчика
`onTouchStart/onPointerDown` — жест не реализован вовсе:

```
$ grep -rn "onTouch|onPointer|touchstart|pointerdown|swipe" frontend/src
→ 0 совпадений
```

## Ожидаемый результат (docs/frontend/spec-ui.md, экран «Свайп-лента»)

- Свайп влево → `POST /vacancies/{id}/candidates/{uid}/action
  {action:"skip"}`; свайп вправо → `invite`. После действия показывается
  следующая карточка.
- Хаптика: `HapticFeedback.impactOccurred('light')` на свайп.
- Кнопки остаются как альтернатива (в макете Direction A — именно кнопки
  «Пропустить/Пригласить» под карточкой).

## Примечание

Жест отсутствовал и до редизайна T-31 (в старой ленте были только
кнопки ✕/♥) — т.е. это не регрессия вёрстки, а нереализованная по спеке
фича, которая стала заметна после приведения экрана к макету.

## Как чинить (предложение)

Pointer Events на карточке: `pointerdown/move/up`, порог ~80px и
сопротивление на середине, поворот карточки по `transform`, по
пересечению порога — `candidateAction(...)` + хаптика; учитывать
`touch-action: none` на карточке, чтобы не конфликтовать со скроллом.

## Фикс

- Pointer Events на карточке подбора: drag порог 80px, поворот
  `rotate(dx/24deg)`, `touch-action: pan-y` (вертикальный скролл не
  ломается). Свайп вправо → invite, влево → skip, хаптика как была.
- Файл: `recruiter/feed.tsx`.
- Проверено вживую: драг мышью перевёл карточку на следующего
  кандидата.
