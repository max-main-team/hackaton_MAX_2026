# Реверс-найм — мини-приложение для MAX

Мини-приложение, где поиск работы перевёрнут: **кандидат один раз заполняет резюме,
а компании сами находят его** под свои вакансии и присылают приглашения с дедлайном.
Взаимное «да» превращается в матч с контактом рекрутера.

## 1. Работающее решение в MAX

- **Открыть мини-приложение:** <https://max.ru/t599_hakaton_max_bot?startapp=..>
  (параметр `startapp` передаёт реферальный код `ref_<id>`)
- **Мини-приложение (прод):** <https://eclipse-sim.ru> — открывается внутри MAX;
  авторизация проходит автоматически по `initData` мессенджера.
- **Без MAX** (браузер): та же ссылка → кнопка **«Демо-вход»** создаёт тестового
  пользователя (ID 700000000–799999999) — весь основной сценарий проходится и так.

Git-репозиторий: `github.com/max-main-team/hackaton_MAX_2026`.

## 2. Назначение и основной сценарий

**Назначение:** убрать рутину откликов. Кандидат заполняет анкету один раз,
компании получают ранжированный подбор и приглашают за один клик.

**Сценарий кандидата:**

1. Вход в мини-апп из MAX → выбор роли «Кандидат».
2. Резюме: вручную или загрузкой PDF — текст извлекается, AI раскладывает
   его по полям (должность, навыки, опыт, город, формат, зарплата).
3. Подтверждает активность — попадает в подборки компаний.

**Сценарий компании:**

1. Выбор роли «Рекрутер» → создание компании (можно верифицировать токеном бота).
2. Создание вакансии: навыки, опыт, город, формат, зарплата, TTL приглашения.
3. Подбор: карточки кандидатов со скорингом соответствия (свайп/список)
   или вкладка «Кандидаты» — все активные резюме с поиском, вне метчинга.
4. «Пригласить» → у кандидата появляется приглашение с дедлайном.

**Ответ кандидата:** принял → матч, обеим сторонам виден контакт рекрутера;
не успел до дедлайна → статус `overdue`, ответ блокируется (409).

## 3. Состав и архитектура

```
MAX клиент (мини-апп) ──► frontend: nginx, React SPA (порты 80/8081)
       │ /api/*                 │
       │                        ▼
       │                 backend: Go + Echo (порт 8080)
       │                        │
       │                        ├─► PostgreSQL 17 (порт 5432 внутри, 5433 наружу)
       │                        ├─► Bot API MAX (platform-api2.max.ru) — бот и рассылки
       │                        └─► z.ai (OpenAI-совместимый LLM) — скоринг и парсинг
```

| Компонент | Технологии | Папка |
|---|---|---|
| Бекенд | Go 1.27, Echo v4, pgx v5, миграции (embed) | `backend/` |
| Фронтенд | React 19, TypeScript, Vite 8, nginx | `frontend/` |
| База | PostgreSQL 17 | сервис `postgres` |
| Воркеры | внутри бекенда: бот (long polling) + еженедельный опрос | `backend/internal/worker/` |

Подробности — [`ARCHITECTURE.md`](./ARCHITECTURE.md), [`docs/`](./docs/README.md),
живой контракт — Swagger `https://eclipse-sim.ru/api/docs`.

## 4. Запуск одной командой (Docker)

```bash
docker compose up -d --build
```

Поднимает **все** компоненты: Postgres + бекенд (с миграциями) + фронтенд.

| Что | Где |
|---|---|
| Мини-апп (SPA) | `http://localhost:8081` |
| API бекенда | `http://localhost:8080/api/v1/*` |
| Swagger | `http://localhost:8080/swagger/index.html` |
| Postgres (наружу) | `localhost:5433` (внутри сети — `postgres:5432`) |

**Остановка:** `docker compose down` (данные БД остаются в volume `postgres_data`).
**Повторный запуск:** снова `docker compose up -d --build` (либо без `--build`,
если код не менялся). Полный сброс данных: `docker compose down -v`.
Только база для разработки бекенда: `docker compose up -d postgres` + `make run`.

## 5. Параметры и переменные окружения

`.env.example` в корне (копия в `.env` при необходимости; значения по умолчанию
позволяют запуститься без конфигурации; рабочих токенов нигде нет):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `JWT_SECRET` | dev-значение | подпись JWT; для прода задать свой секрет |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | `postgres` / `postgres` / `maxapp` | доступ к БД |
| `DATABASE_URL` | собирается из значений выше | строка подключения бекенда |
| `MAX_BOT_TOKEN` | — | токен бота MAX: проверка подписи initData, команды бота, рассылки |
| `AI_API_KEY` | — | ключ z.ai: AI-скоринг пар и AI-парсинг PDF-резюме |
| `AI_BASE_URL` / `AI_MODEL` | `https://api.z.ai/api/paas/v4` / `glm-4.5-flash` | эндпоинт и модель LLM (OpenAI-совместимый API — подставляется любой провайдер, например Яндекс GPT или GigaChat) |
| `VITE_YANDEX_MAPS_API_KEY` | — | ключ Яндекс Карт, встраивается во фронтенд при сборке |
| `ADDR`, `ENV` | `:8080`, `dev` | адрес слушателя и режим бекенда |

## 6. Зависимости и внешние сервисы

- **Файлы зависимостей:** `backend/go.mod` + `backend/go.sum` (Go-модули),
  `frontend/package-lock.json` (npm). В Docker зависимости ставятся на этапе
  сборки (`go mod download`, `npm ci`).
- **Внешние сервисы и интеграции:**

| Сервис | Назначение |
|---|---|
| Bot API MAX (`platform-api2.max.ru`) | команды бота, приветствия, еженедельный опрос, проверка подписи `initData` |
| z.ai (LLM, OpenAI-совместимый API) | AI-скоринг пар «вакансия↔резюме», AI-парсинг PDF-резюме. Провайдер легко меняется: любое OpenAI-совместимое API — Яндекс GPT, GigaChat и др. — достаточно заменить `AI_API_KEY`, `AI_BASE_URL` и `AI_MODEL` |
| Яндекс Карты (JS API) | карта вакансий |

## 7. Работа с данными

- Единственное хранилище — PostgreSQL 17. Схема создаётся **автоматически**
  при старте бекенда из `backend/migrations/*.sql` (embed, 8 миграций:
  пользователи, компании/вакансии/резюме, действия рекрутеров, рефералки,
  AI-оценки, статусы парсинга).
- Храним: профили и роли, резюме (плюс полная история версий и исходный текст
  PDF — только с согласия пользователя), компании и членство, вакансии,
  приглашения и ответы, реферальные связи, кеш AI-оценок, тех-логи клиентских
  ошибок (`/debug/log`).
- Файлы PDF **не сохраняются**: на сервере остаётся только извлечённый текст.
- Миграции идемпотентны (`schema_migrations`), повторный старт безопасен.

## 8. Тестовые данные

- **Демо-вход** — самый быстрый путь: кнопка «Демо-вход» на экране входа
  (или `POST /api/v1/auth/demo`) создаёт тестового пользователя
  в диапазоне ID 700000000–799999999, роль выбирается на онбординге.
- **Сид демо-данных** — `scripts/seed_demo.py`: наполняет базу компаниями,
  вакансиями и резюме СПб (идемпотентно, демо-пользователи 900000001+):
  ```bash
  BOT_TOKEN=<токен бота> python3 scripts/seed_demo.py
  ```
  Без сида сценарий проходится с чистой базой: зарегистрируйте одного
  кандидата и одну компанию вручную.
- Ответ на еженедельный опрос — кнопки «Актуально»/«Не ищу работу»
  на экране резюме (`POST /my/resume/confirm-activity`).

## 9. Пошаговый сценарий проверки

| Шаг | Действие | Ожидаемое поведение |
|---|---|---|
| 1 | Открыть мини-апп из MAX (или «Демо-вход» в браузере) | экран онбординга с выбором роли |
| 2 | Кандидат: выбрать роль, заполнить резюме (или загрузить PDF) | через 30–90 сек поля заполнены AI, баннер «Резюме распознано», после «Сохранить» — «Сохранено» |
| 3 | Второй пользователь (или второй браузер): роль «Рекрутер», создать компанию и вакансию (TTL 24) | вакансия в списке, статус «активна» |
| 4 | Открыть подбор по вакансии | карточки кандидатов со score 0–100 и разбором (навыки/город/формат/опыт); у AI-режима — `ai_score` и комментарий |
| 5 | Вкладка «Кандидаты» | все активные резюме независимо от метчинга; поиск по «postgres» сужает список |
| 6 | «Пригласить» кандидата | карточка исчезает из подборки; при исчерпании квоты — 409 и подсказка про рефералку |
| 7 | Кандидатом открыть «Приглашения» | приглашение с обратным отсчётом; «Принять» → матч-экран с контактом рекрутера |
| 8 | Просроченное приглашение (TTL истёк) | статус `overdue`, попытка ответа → `409 invitation expired` |
| 9 | Карта вакансий | пины активных вакансий по городам |
| 10 | `GET /api/v1/health` | `{"status":"ok","db":"ok"}` |

Автоматический аналог шагов 3–8 описан в `DATA-API.yaml` (проверки формата
DATA-API 1.0, валидатор организаторов проходит с кодом 0).

## 10. Полезные команды

```bash
docker compose up -d --build      # всё решение (Postgres + бекенд + фронтенд)
docker compose logs -f backend    # логи бекенда
docker compose down               # остановить (данные сохраняются)

cd backend  && make run           # бекенд без Docker (нужна БД на :5433)
cd backend  && make test && make vet && gofmt -l .
cd frontend && npm run dev        # Vite на :5173 c прокси /api → :8080
cd frontend && npm run lint && npm run build
```
